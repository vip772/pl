# 首次切页、滚动与加号菜单优化

基线c96b1fd；输入125708运行日志与同版本mapping、两张菜单截图。mapping确认oi.n0为透明Drawable、oi.o0为屏幕对齐图片Drawable。微信内部结构核实8.0.78。用户仍要求不运行本地Gradle或APK构建。

## 证据与修改

- 原四页透明内容共用Decor底图，只有当前页选中才开始加载图片，因此异步图片就绪前会露出上一页底图。现在按页面创建事件准备图片，启动后台继续预加载通讯录/发现/我，并将各页图片绑定到各自fragment根；窗口底图保留用于公共区域。临近页面有准备好的图片时同步挂载，配置revision变化清空预热引用。每页图片不再等待选中后才首次准备。
- 原列表pre-draw在每一行内findActivity，移到每次回调一次。标题栏全局布局每次都查询账号资料、搜索标题宿主、遍历TaskBar树；现在已附着标题直接复用，资料查询至少间隔1500ms，重复标题树扫描至少间隔1000ms，显隐与尺寸仍即时响应。不是持续定时器，不新增空闲轮询。
- CHROMEDRAW原每次聊天刷新扫描整树并记录几十项，日志中visited=1801；本次每种reason仅保留首份树快照，定向限频日志继续保留。
- AppGrid的适配器com.tencent.mm.pluginsdk.ui.chat.c.getView(Int,View,ViewGroup)已由classes12.dex确认。layout/hw中a11独立选择背景、a10图标，条目复用时重绑；底栏240节点扫描无法稳定覆盖后创建的格子。现在getView返回前清理条目容器、普通View及ImageView背景/前景，保留文字、点击、红点和图标内容。
- Adapter按holder.p确认favorite/contact_card/file/voice_input/transfer/card/music等业务键；部分使用panel_icon资源，白底可能属于图像本身。为这些指定条目使用APK存在的透明icons资源，保存NativeImageSnapshot以恢复，新增CHATPART app-grid:key。未修改其他业务图标和发送行为。
