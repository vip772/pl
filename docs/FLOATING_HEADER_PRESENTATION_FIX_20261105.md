## 源码证据
1. `FloatingChatHeaderCapsule.apply` 在尺寸、原生返回/标题/更多入口或菜单唯一性未就绪时调用 `fail`。`fail` 保留仍挂在同一header的已安装胶囊；初次安装未就绪返回false。
2. 旧 `FloatingChatHeaderFeature.apply` 对任何false均调用 `FloatingChatCardVisuals.apply(header, ...)`，并设整栏阴影和裁剪，将原生入口瞬时可用性当成外观模式选择。
3. 整栏背景固定RGB为浅色 `#F7F7F7` / 深色 `#242424`，与三段半透明胶囊不同。因此确认有可达的整栏灰底回退代码，但未发现独立“灰色模式”配置。
4. 胶囊的 `#242424` 深色表面是正常暗黑适配；头像的 `0x44808080` 是局部占位。没有证据说明应删除这些正常视觉元素。
5. 沉浸式 `installBackgroundWriteHook`、`setTransparentSurface`、`restoreSurface` 已检查悬浮卡片所有权；ActionBar三层清空/回写/恢复检查独立所有权；胶囊挂载前声明展示所有权。没有证据支持直接删除这些恢复机制，也没有实机证据彻底排除交互问题。
