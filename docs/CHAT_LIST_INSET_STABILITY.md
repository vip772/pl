# 聊天列表底部避让稳定性核查

基准：4f43b1c。证据：Hchat-runtime-20261029-002525.log 和用户截图；映射附件包含 mapping.txt，日志无本问题相关异常栈，不需反混淆推测。

日志首次 list-padding：base=374、overlap=380、target=754。原生 MMChattingListView 初始化只设置 6dp 底边距，因此不能把 374px 当成正常初始常量。源码存在沉浸式背景输入穿透与悬浮输入框分别捕获底边距的路径：前者虽在配置开启时恢复，但异步回调顺序不能保证在后者首次捕获前恢复。新代码显式交接旧避让；没有按数值猜测扣除 374px。

同一列表的日志还记录 listY/listH/footerY 在父容器布局中变化，目标在 754/625 间变化。原来的 recycler.onLayout 前置处理允许使用仍在布局中的祖先坐标。现在遇到祖先待布局时延后到有限 pre-draw 收尾，已就绪实例也能进入最多三次的收尾。稳定调用没有新任务。

ChatListBottomInset 原实现只在正向溢出时 scrollBy，边距缩小时保留空白，且重复 beforePadding 会清空尚未消费的锚点。现在同一事务保留锚点，边距增减都维护原本已在底部的列表。历史、短列表、拖动、惯性滚动、追加/删除消息的保护仍保留。

关联功能：悬浮标题栏只改列表顶部避让且保留下边距；工具栏作为输入区子项参与高度测量；消息显示时间修改行内标签、会话时间样式修改原生时间文本，未发现直接写列表底边距。这不等于排除所有真机偶发情况，当前定位集中在上述可验证的布局链路。

验证：生产辅助类 JVM 测试覆盖避让交接、祖先待布局、避让缩小及连续调用保留锚点；Android SDK 联合编译；输入穿透、面板、顶部避让、消息详情布局/缓存重挂载、背景边距归属、时间解析回归通过。没有新增逐帧反射、滚动监听或轮询。新增父链检查只在既有布局更新入口执行；底部补偿只消费一次已捕获锚点。

限制：尚未安装候选 APK、未做真机帧耗时比较，不能宣称截图问题或性能已验收。整体 Gradle 编译结果另行核对。
