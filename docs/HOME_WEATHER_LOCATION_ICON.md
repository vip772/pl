# 首页与侧边栏天气定位图标

## 当前布局（2026-11-03）
- 首页扩展、紧凑卡片和侧边栏共用 `HomeWeather.card`。
- 标题的地区行固定按“定位按钮 → 地区名称”排列；标准布局的更新时间在右侧，紧凑布局的更新时间在地区行下方。
- 定位针仍使用 `WeatherLocationDrawable`，保留 48×48dp 点击区域、无障碍说明、忙碌禁用和点击定位后强制刷新。
- 本次根因是定位按钮此前被追加到 `heading` 最末，位于更新时间右侧；仅调整父子顺序，不改天气请求、定位监听器或缓存。

## 本轮追加：3小时更新与县区显示
- 首页扩展和侧边栏继续共用 HomeWeather.card，缓存有效期由6小时改为3小时；原有侧边栏头像6小时缓存无关，保持不动。
- 原实现仅在 attach 时判断过期。本轮增加每张已挂载天气卡片单个延时回调，按缓存到期时刻更新；detach 取消，重新显示时检查过期。没有系统常驻服务或唤醒锁，微信暂停执行期间不保证整点联网。失败保留5分钟退避、相同坐标请求去重。
- 原地区字符串为“市 · 县区 · 省”，界面只取第一段，导致县区被隐藏。本轮优先选择 Android 地址中的县/区/旗，作为首段；市名保留为后续上下文。
- Android只给市或乡镇时，在既有串行天气线程使用现有和风GeoAPI进行一次坐标反查；参数为经度,纬度，地区name排在adm2/adm1前。官方依据：https://dev.qweather.com/docs/api/geoapi/city-lookup/ （本轮已读取；示例name为东城，adm2为北京）。不猜县名，不把市名伪装成县。若定位或地理服务未返回县级数据，仍可能降级为可用地区/坐标，设备验证必须覆盖此边界。
- 经纬度天气缓存不随地区文字变化而清空；持久化到对应入口原有偏好。保留定位20秒超时、removeUpdates清理、异步结果坐标/请求代次/挂载状态/当前配置守卫，防止旧结果覆盖新选择。
- 验证：test_weather_county_schedule_source.py 为源码断言和Python参考模型，不运行Kotlin/Android；test_weather_moments_surface.py为源码与原生证据检查。未进行任何本地编译、构建、安装、3小时实机计时、县区定位或界面验收。
