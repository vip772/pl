# 群聊分析生成等待与异常换行修复

最新行为已由 [最新消息与正文解析修订](CONVERSATION_ANALYSIS_LATEST_MESSAGES_FIX.md) 更新，以下为早期改造记录，旧均匀抽样和自动容量映射不再生效。

## 源码确认的问题

生成前原先通过数据库 query 把所选时段全部文本逐行转为 Map 和字符串，再做均匀采样。自动模式按模型容量发送最多 3000/6000/12000/25000/50000 条，每条最多 600 字符，输入量较大。流式刷新时正文容器重复移除并创建 TextView；对已结束但未发送 `[DONE]` 且不关闭 HTTP 的 SSE，解析器仍会等待下一行。

输出处理缺少对模型正文中额外转义的换行及重复 `/n` 的修复。没有本次用户实测的原始响应或阶段耗时，不能认定异常标记由某个服务端生成，也不能量化数据库、网络、模型各自占比。

## 修改

- 复用公共数据库 rawQuery，保留原 SQL 时段和类型过滤，Cursor 按均匀索引读取，仅将采样行实体化。Cursor 通过 use 在成功、异常、取消时关闭，查询失败单独提示，不当作没有聊天记录。Cursor count 和窗口装载仍可能扫描所选时段；没有宣称消除数据库全部扫描。
- 自动模式按 128K/256K/512K/1M/2M 调为最多 300/600/1200/2500/5000 条。保留用户手动条数及 50000 上限，设置界面说明抽样可能遗漏细节、调高数量会延长等待；不改写已有配置。单条 600 字符和原昵称缓存保持。
- 增加读取消息、已抽样并等待首段正文两个状态。它们是准备状态，不能用作首段 AI 正文已经到达的证据。
- 继续请求 stream=true，首段立即回调，后续约 250ms 节流；遇到 finish_reason 即结束，避免等待保持打开的连接。仍支持 `[DONE]`、CRLF、心跳、多行事件和断流错误。明确返回 application/json 的接口仍只能等待完整 JSON。
- 流式快照、最终正文、页面及截图数据使用统一规范化：真实 CRLF/CR、字面量和双重转义换行、连续 `/n`，过多空行收敛为两个换行。保留普通 `/news`、HTTP(S)/www URL 和盘符 Windows 路径；没有尝试通用解码任意转义。新增提示词要求真实换行。
- 正文只创建一个 TextView，后续更新样式文本；内容相同跳过重绘，截图使用相同清理后的正文。保留原字号、颜色、行间距和成员 ID 清理。

## 验证与边界

`python3 scripts/test_analysis_generation.py` 执行实际采样、文本辅助类及提取的实际初始化/渲染代码：转义、双重转义、CRLF、连续 /n、跨分片快照、URL/路径、幂等、均匀有界索引、1000 次更新复用同一 TextView、相同内容不触发布局。

`python3 scripts/test_analysis_period_linkage.py` 执行真实 AI 取数前缀并配显式 Cursor 桩：日期先过滤再采样、仅读取抽中正文、关闭、取消、SQL 失败和空记录不发 HTTP。测试桩自身用内存列表模拟数据库，不是 Android SQLite 性能测量。

`python3 scripts/test_analysis_stream.py` 用管道验证首段在 EOF 前到达，以及 finish_reason 后无需 DONE/EOF 即返回；覆盖原有 framing、节流、取消及昵称缓存。

同时回归 API 配置、弹窗测量、页面生命周期、自动勾选合并、头像及备份；使用 SDK 与既有 ABI 直接编译受影响完整群聊分析源码及合并源码。原始本地日志在 `/tmp/pl-summary-verify/`，不可视为可跨设备持久访问的文件。
