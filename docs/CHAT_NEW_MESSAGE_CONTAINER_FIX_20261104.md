## 精确定位

1. 原始 APK `r/p/ss.xml` 的二进制布局和资源表确认：`bki=0x7f0a0f73` 是 `ChattingContent`；`bm4=0x7f0a0fc0` 和 `bm2=0x7f0a0fbd` 均为其直接子项；`ChatFooter` 是内容容器之后的同级输入区。
2. `smali_classes11/.../component/hh.smali` 的 `a()` 获取 `bm4`；`S0(I)` 使用 `0x7f100d26`（`b2_`，`%d条新消息`）并设置点击监听；`R0(IZ)` 对同一对象设置顶部或底部 gravity。因此“条新消息”必须处理 `bm4`。
3. `smali_classes8/.../component/sk.smali` 的 `a()` 获取 `bm2`，同一方法的原生标识为 `QuoteMsgTongueComponent`。旧修复只处理该引用提示，不能覆盖截图中的实际新消息目标；旧文档把 `hh` 对应到 `bm2` 的说法已纠正。
4. 旧 feature 在工具栏关闭时销毁运行时，旧 rebuild 关闭观察者；即使修正目标，也缺少工具栏关闭时的输入框避让。
5. `ChatInputMessageUnderlay` 源码只扩展内容区域而保留 footer 位置和触摸边界；`ChattingContent.onLayout/onMeasure` 调用 FrameLayout，`ChattingScrollLayout.dispatchTouchEvent` 保留原生事件分派。因此避让需同时满足可见锚点、footer 整体命中区域和内容父容器范围，而非仅提高绘制 Z。

完整原生证据哈希见同名 JSON。解码文本的 XML 存在历史格式损失，本次父子关系以原始二进制布局的 `aapt2 dump xmltree ... --file r/p/ss.xml` 为准。

## 修改行为与开销约束

- 对 `bm4`（新消息/历史消息）和 `bm2`（引用提示）分别保存位移基线及最后写入值；只移动可见底部 gravity，顶部历史提示继续走原生/现有标题栏逻辑。
- 工具栏可见时锚定其顶部，否则锚定 `ssr` 输入行；同时限制提示底部在 footer 顶部和 content 底边之上，间隔8dp，完整提示不能越出 content 顶边。
- 不改父容器、原生布局参数、边距或点击监听，不增加触摸转发、点击替身、透明全屏层、全局 Hook 或 Z 顺序改写。原生消息定位和点击动作由微信继续负责。
- footer 观察者不随工具栏显示状态销毁。关闭工具栏隐藏模块行、清除按钮、关闭面板安装票据；面板采集、测量和主动初始化均检查开关。再次启用创建新票据，已有 grid Hook 时也刷新已知面板，避免开关后按钮空白。
- 缓存两个目标，仅子项数量或旧对象父链变化时重新解析；隐藏/顶部提示跳过屏幕坐标读取；复用数组，不轮询、不加线程、不在稳定帧请求布局或重复写相同位移。销毁/detach/异常移除观察者，位移恢复遵守所有权。
- 仅对已确认的微信8.0.78/3180生效。其他版本未建立对应原生证据，不扩展混淆映射或宣称兼容。
