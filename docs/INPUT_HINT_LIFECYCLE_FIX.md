# 输入框提示偶发消失：事件覆盖修正

## 根因与处理
原实现只在 ChatFooter.onAttachedToWindow 后立即绑定并 post 补设一次。微信挂载后调用 ChatFooter.setHint(CharSequence) 会覆盖提示；输入控件在第二次查找后才就绪或被替换，也没有重新绑定入口。

现在保留挂载入口，并加入 ChatFooter.setHint 的后置处理。对已观察的 ChatFooter 添加单个布局变化监听，实际发生布局变化时重新核对当前输入控件；布局回调不投递延后任务。挂载和原生提示更新只合并投递一次补查，无固定延迟轮询、不监听每帧预绘制、不全局 Hook TextView.setHint。

提示仍是已应用的同一实例时跳过模板渲染与写入；配置/统计更新仍主动刷新以保留颜色等变化。模块写提示时设递归保护。关闭功能恢复保存的原生提示，运行时销毁时移除布局监听与自身 Hook，并使迟到绑定任务失效。不清空草稿、不改输入文字；有输入文字时 hint 不显示仍属原生行为。

## 验证与限制
- scripts/test_input_hint_lifecycle.py 提取完整生产 InputHintRuntime，在事件驱动宿主模型执行：晚于首次补查就绪、控件替换、原生空/非空提示覆盖、重复1000次布局不写提示、关闭/重新开启、代理输入递归及销毁清理。
- 完整生产运行时通过 Android SDK36 定向编译，微信与项目依赖为桩，不是整工程构建。
- 微信入口逆向证据为本地8.0.78 ChatFooter.onAttachedToWindow、setHint及其向输入接口转发调用。未取得其他默认版本的相应结构证据，不能宣称完成跨版本验证；安装会检查具体方法签名，缺失时报告失败。
- 不拦截所有直接写入具体输入控件的 setHint；若有绕过 ChatFooter 的调用且此后无布局/统计事件，仍可能需要新日志补充定位。布局监听也不保证发现完全不触发布局的控件替换。
- 未运行Gradle、未构建APK、未操作微信；实机提示持续显示、输入性能与版本兼容仍待验收。
