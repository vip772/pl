# 输入框提示偶发消失：事件覆盖修正

## 根因与处理
原实现只在 ChatFooter.onAttachedToWindow 后立即绑定并 post 补设一次。微信挂载后调用 ChatFooter.setHint(CharSequence) 会覆盖提示；输入控件在第二次查找后才就绪或被替换，也没有重新绑定入口。

现在保留挂载入口，并加入 ChatFooter.setHint 的后置处理。对已观察的 ChatFooter 添加单个布局变化监听，实际发生布局变化时重新核对当前输入控件；布局回调不投递延后任务。挂载和原生提示更新只合并投递一次补查，无固定延迟轮询、不监听每帧预绘制、不全局 Hook TextView.setHint。

稳定提示按文本与样式语义比较，而不只比较对象实例；配置/统计更新合并刷新并使渲染缓存失效，以保留颜色等变化。模块写提示时设递归保护。关闭功能恢复保存的原生提示，运行时销毁时移除布局监听与自身 Hook，并使迟到绑定任务失效。不清空草稿、不改输入文字；有输入文字时 hint 不显示仍属原生行为。

## 验证与限制
- scripts/test_input_hint_lifecycle.py 提取完整生产 InputHintRuntime，在事件驱动宿主模型执行：晚于首次补查就绪、控件替换、原生空/非空提示覆盖、重复1000次布局不写提示、关闭/重新开启、代理输入递归及销毁清理。
- 完整生产运行时通过 Android SDK36 定向编译，微信与项目依赖为桩，不是整工程构建。
- 微信入口逆向证据为本地8.0.78 ChatFooter.onAttachedToWindow、setHint及其向输入接口转发调用。未取得其他默认版本的相应结构证据，不能宣称完成跨版本验证；安装会检查具体方法签名，缺失时报告失败。
- 不拦截所有直接写入具体输入控件的 setHint；若有绕过 ChatFooter 的调用且此后无布局/统计事件，仍可能需要新日志补充定位。布局监听也不保证发现完全不触发布局的控件替换。
- 未运行Gradle、未构建APK、未操作微信；实机提示持续显示、输入性能与版本兼容仍待验收。

## 聊天滚动优化第一阶段（2847193 基线，本地待实机验证）

本轮有效采样为 Stacks284-Retest-20261025-225759：99Hz、7.95058秒、369样本、丢失0。输入框提示绑定链含子调用7.44%，applyHint 5.99%、writeHint 3.61%，相互包含不能相加；采样含滑动前后，不能视为帧耗时或全部冗余。艾特提醒由用户确认关闭。

原模型TextView保留提示对象身份，漏测Spanned复制。新增复制带颜色提示的模型后，原生产运行时在稳定布局检查失败，优化版本通过。这证实旧快路径对复制对象不稳健，不等于实机所有写入均由此造成。

- 使用文本、span类型、值、范围和flags比较；ForegroundColorSpan按颜色值，模块渐变span按起止颜色值比较。未知span保守比较身份或equals，避免只按文字吞掉样式变化。
- 模板渲染结果由事件版本缓存，配置/统计回调在主线程合并刷新；多控件复用当前结果。原生覆盖时可复用渲染结果恢复，不必重读统计和重建所有span。
- 统计开启时缓存至下一本地日界，后续绑定过期重新读取，避免无限缓存旧日数据。没有新增午夜定时器，静止页面跨日刷新仍依赖后续事件；时区/系统时间动态变化未专项验证。
- 保留挂载、footer.setHint后置处理、布局检查、一次延后补查和递归保护。不删除控件替换识别，不修改输入文字或草稿。稳定布局仍有轻量绑定、读hint和样式检查成本，不宣称零开销。
- 扩展模型覆盖3000次稳定布局无重复渲染/写入、对象复制、同文字颜色变化、样式被清空后恢复、模板变化、刷新突发合并、统计更新、缓存到期、控件替换、关闭恢复、递归和销毁前已排队任务。
- scripts/test_input_hint_sdk.py对生产运行时及InputHintSettings同时进行SDK36定向编译；模型样式对象并非真实Android TextView，真实渐变复制及输入法交互仍待新包验证。

本阶段不修改背景透明扫描、底部锚点、聊天时间解析和艾特提醒。未运行Gradle、未构建APK、未提交推送。下一阶段必须安装包含本地改动的新包及对应mapping后，同条件复采调用栈和帧耗时，再决定是否优化背景处理；当前手机2847193不含本地优化，不能用于声称优化后实测。
