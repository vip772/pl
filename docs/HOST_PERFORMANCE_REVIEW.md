# 宿主运行开销检查与定向优化

本轮扫描 app/src/main/java/t/mma 下 721 个 Java/Kotlin 文件，按全局 Hook、逐帧回调、位图缓存、同步 I/O 与线程任务筛选，并重点阅读公共 Hook 注册、事件分发、Dex 安装调度、日志存储及部分界面/图片功能。此为静态筛查与选定路径验证，不代表所有功能都经过实机性能测量或逐行审计。

## 本轮保留的修改

- HookRegistry：写时复制列表替换为短锁保护的 ArrayList，减少逐个安装 Hook 时的累计数组复制。卸载使用快照，在锁外调用宿主解除操作；保留快照之后并发新增的句柄，清理后收缩数组容量。Hook 回调本身不获取此锁。
- CustomFriendAvatarStore：SHA-256 的十六进制转换改为固定字符表和字符数组，保留原文件名，减少每字节 Formatter 与中间字符串分配。
- RuntimeLogStore：日志裁剪、读取仅分配所需尾部缓冲，不再先读取整个文件再复制。保持原有字节截取、编码、日志开关、写入线程和导出内容语义。

## 已发现但本轮未修改

- 自定义好友头像缓存为无容量上限的强引用映射，并预加载所有配置头像。1024×1024 ARGB_8888 位图像素约为 4 MiB，实际大小以 allocationByteCount 为准。简单增加 LRU 会破坏预加载命中、触发同步重新解码，因此未保留试验性淘汰改动。需结合实际配置数量和异步加载方案进一步评估。
- 沉浸背景、气泡、头像、侧栏图片均有位图驻留成本；界面持有的位图不随缓存淘汰立即释放。不能将缓存上限当作进程总内存上限。
- 悬浮输入、底栏、动态角标等含预绘制维护或动画路径。不能统一降频，否则可能改变跟随、反馈和原生改写后的修复时机。
- 事件总线同步调用订阅者；脚本发送按钮回调也在主线程。任意用户脚本的耗时不由静态项目扫描保证。

## 验证与边界

修改的三份生产源码通过 Android 36 SDK 定向编译；项目依赖和 Xposed 使用测试桩。专项 JVM 验证覆盖 8 线程 8000 次句柄注册、批量解除、解除期间新增句柄保留，SHA-256 文件名一致性，以及空文件、512 KiB 边界和 8 MiB 文件的日志尾部字节一致性。测试工具留在 /tmp，不是正式产物。
