# 群聊分析时段联动核查与修复

## 已确认问题

- 总结按钮虽传递所选整数，但 AI 的原范围计算将昨日/上周/上月的负数强制归为1，实际读取今天。
- 原本周/本月采用最近7/30天，上周采用最近7天截至昨天，不符合自然周/月名称。
- 深度图表首次加载后固定使用初始时段；排行日期切换只刷新排行，其他图表没有联动。
- 页面和截图日期文字另有独立算法，负数时段显示错误；60天活跃检测被误当全部历史。

## 修改行为

- 新增 ConversationAnalysisPeriod：统一今日、昨日、自然周（周一开始）、上周、自然月、上月、全部历史的毫秒闭区间。当前时段截止查询时刻，历史时段截止下一时段开始前1毫秒。Calendar按设备本地时区处理跨年、闰月及夏令时。
- AI取数、核心指标、深度统计、页面日期与截图日期复用同一范围规则。先按时段查询再采样，无文本时段不发送AI请求，也不回退其他日期。
- 总结时段与排行时段共享页面内选择状态。任一入口切换，刷新高频语义、情绪指纹、废话程度、多维属性、全天活跃频次，以及排行、作息和内容载体偏好。核心指标同步，历史消息总数仍表示全部历史。
- 切换时立即显示读取状态，完成回调校验递增序号，旧查询不能覆盖新时段。旧AI请求关闭、旧报告引用及内容清除、截图按钮禁用，防止旧报告被误认成新时段结果。
- 群聊活跃检测的“最近N天”滑块保留独立语义，调用recentDays，不将7/30/60天误作自然周/月/全部。
- 取消旧的重复核心指标加载入口，避免其初始今日结果覆盖后来选择。
