# 原生群昵称开关联动

## 行为
当前群关闭微信原生“显示群成员昵称”后，群昵称、群员头衔、实名尾字一并隐藏。重新开启后随微信下一次昵称绑定恢复各功能原有配置。群间独立，不写原生设置和模块用户配置。原生开关开启但成员昵称为空时，保留原来的显示名兜底。

## 已确认的原生证据
微信 8.0.78：`com.tencent.mm.ui.chatting.viewitems.b0.p(h0,gk5.d,e9,String)` 的昵称绑定读取 `ChatroomComponent` 实现 `q2.e:Z`；`q2.w0()` 从群记录 `field_isShowname > 0` 更新该值。该组件通过 `gk5.d.a(Class)` 获取，生命周期 `A()`、`x()` 调用 `w0()`。因此不能用 userTV 的 VISIBLE/GONE 代替原生开关。

`NativeGroupNicknameGate` 在安装阶段由现有昵称绑定方法读取的 boolean 字段，与读取 `field_isShowname` 的无参 void 方法所写字段求交集，严格要求唯一结果。不硬编码上述混淆名。通过实时 runtimeKey 缓存刷新方法和字段描述符，缓存命中不重跑 DexKit。无法确认入口时暂停头衔、尾字安装并记录原始异常，交由现有调度器有限补装。

## 完整刷新路径
头衔、尾字共用一个带引用计数的原生状态刷新 Hook。绑定时保存当前控件、成员、群和原生组件弱引用；渲染前实时读取组件开关，覆盖头衔群资料刷新、120ms 延迟补绘、实名和资料查询返回。原生刷新为关闭时，清除已跟踪行的头衔/尾字并将 userTV 设为 GONE；不扫描视图树、不查数据库、不新增轮询或滚动监听。重新开启由正常原生昵称绑定恢复。

每次有效绑定覆盖行身份，自己发送和无效发送者移除旧身份，避免过期异步操作重新显示旧昵称。两个渲染器停用时释放共享引用，最后一个使用者退出才解除共享 Hook。实名尾字同时解除自己的绑定 Hook、取消延迟任务，失效回调不再渲染。
