## 第二组：需用户单独授权、仅专用测试账号/群
本组不是默认测试许可。没有明确授权就保持“未测”，不要为了凑齐通过率触发真实业务。
- 表情艾特：普通发送/艾特发送、选择页关闭、搜索页切换、选人时关闭重开；确认一次用户选择仅发一次且原生参数保留。
- 手动转发/群发：极小合成内容测试队列；关闭功能只停止待办，已开始项目走完成或既有超时；主动取消仍按原语义。
- 自动回复/转发/朋友圈：逐项限定测试对象，验证关闭重开不会重放旧代任务。
- 红包/转账：不以真钱支付验证资源生命周期；默认仍未测。独立伪造/新群保护开关不受主开关错误联动。
- 好友检测/删除、朋友圈发布/清除：没有专门授权不执行。

## 资源与性能观察
- 在相同页面、相同功能、相同等待时间下记录 Java heap、native heap、线程数及 Hchat 线程名；至少三轮对比，避免把 GC 波动当优化收益。
- 空闲串行线程预计在任务结束后约 30 秒退出；网络/宿主在途任务可能需等待既有超时。不要用强制中断来“验证回收”。
- 检查关闭后旧代任务是否继续产生 UI/通知/后续发送，而不只看线程是否存在。
- 连续上下滚动与切页，记录明显卡顿及对应时间；如有权限采集帧时长。未测前不填写“流畅度通过”。
- 若重复启停后仍持续增长，保存脱敏日志及操作顺序，回退候选，不盲目多次重试支付或发送。
