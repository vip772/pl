# 艾特扩展

增强分组与新功能聚合页共用 `mention_extension` Provider 和设置页。隐藏艾特、表情艾特、艾特高亮的旧独立Provider、页面和路由已移除；原运行模块继续注册安装，不复制Hook，不改变发送或消息渲染行为。

页面提供三个独立开关，并保留艾特高亮颜色编辑、重置及保存；高亮关闭时隐藏颜色设置。直接使用原来的 Hchat_hidden_at_config/enable、Hchat_emoji_at_config/enable、Hchat_mention_highlight_config/mention_highlight_enable 和 mention_highlight_color，无迁移写入、无默认值覆盖。任一子开关开启即在已开启聚合中显示艾特扩展。搜索隐藏艾特、表情艾特、艾特高亮及原高亮关键词均指向新入口。

旧功能类与配置ID用于兼容已有运行状态，不作为独立设置入口。未新增微信内部定位、反射签名或发送逻辑，不扩展版本兼容性结论。验收检查增强/新功能入口一致、旧入口消失、旧配置保留、三个开关独立、高亮颜色保存与隐藏，以及已有能力行为。未操作微信或发送测试消息；完整Compose布局与实机能力待安装验收。

用户验收状态（982版本后反馈）：首页音乐、输入框表情与＋号面板高度、艾特整合均已由用户确认修复完成；不再作为待测试项。此状态来自用户反馈，非本轮自动化实测。

## 艾特提醒

新增默认关闭的“艾特提醒”开关，覆盖真实艾特当前账号及普通 @所有人（notify@all）；群公告单独的 announcement@all 不触发。复用公共消息观察 API，排除自己发送、私聊和未知账号，只对具有服务端消息 ID 的群消息生成本地系统提示：“[艾特提醒] 张三 艾特了你”或“[艾特提醒] 张三 艾特了所有人”。同一消息同时包含两种艾特只插入一次。

提示通过与防撤回相同的 WeChatLocalMessageApi.insertSystemMessageAt 插入到原消息时间之后，以红色 #E53935 展示。不发送网络消息；成员显示名称优先使用群成员显示名。着色复用现有系统消息文字处理 Hook，不额外安装 TextView 全局 Hook；艾特提醒独立确保该共享 Hook 已安装，不依赖退群监控开关。关闭后停止新提醒及红色处理，已插入的本地提示保留。

后台有界串行队列处理，空闲线程可退出。持久化去重按当前账号、群和服务端消息 ID 隔离；插入前写入去重预留，明确插入失败释放，异常/崩溃窗口优先避免重复，极端情况下可能漏一条提示。无服务端 ID 时不猜测消息身份。首次开启不会扫描历史消息；公共观察器数据库兜底仅消费新鲜插入事件，不能保证系统离线补拉消息全部提醒。

验证范围为当前微信 8.0.78 及现有公共 API；未新增微信内部定位。定向编译与模型判定用例不能替代实机提醒展示、红色渲染及重启去重验收。

开发验证：真实 WeChatMessage 艾特分类用例通过（直接艾特、普通所有人、混合名单、纯文字拒绝、其他成员、账号缺失与公告区分）；新增运行文件及修改后的时间绑定/转发标签方法定向编译通过，宿主 API 使用桩。现有卡片布局与预绘制队列回归通过。未做完整 Gradle 构建，持久化去重与红色渲染待实机验收。

## 提醒颜色与独立条目修正

新提示移除可见“[艾特提醒]”前缀，仅显示“张三 艾特了你 / 艾特了所有人”。持久内容增加不可见模块标记，以便精确识别；旧前缀提示显示时移除前缀，不批量改写历史数据库。

默认三色均为 #E53935（纯红）。艾特提醒开启后显示独立“提醒颜色”条目，复用动态撤回 ColorPickerRow 的 threeColorGradient 编辑与 DynamicRecallGradient 解析，支持三色文字渐变、即时保存和恢复默认。设置页隐藏艾特、表情艾特、艾特高亮、艾特提醒各为独立卡片，无功能说明文字。

通用文本入口使用高优先级文字渐变 span；现有聊天绑定入口对已确认的系统提示行再次处理，不依赖消息详情开关，限定模块标记或旧前缀，遍历范围只限当前消息行。原先仅在setText前着色没有绑定后处理，本次补齐；不宣称已经证实全部机型的丢色根因。渲染、旧提示去前缀和颜色编辑需新包实机验收。

## 三色提醒跨度越界修复

用户微信8.0.78/Android16日志：NeatTextView.c 在长度42的文本上应用结束位置45的span并崩溃。上一版通用setText前置处理删除3字符不可见标记，与差值吻合；这是本次优先修复路径，仍需实机闭环。现撤销艾特提醒对共享setText Hook的接入，仅在消息绑定结束后按实际控件内容处理；保留原始字符序列和宿主span，只替换模块自己的渐变/隐藏前缀span。旧可见前缀用零宽ReplacementSpan隐藏，不删除字符，避免破坏微信已有偏移。默认红和自定义三色配置不变。

艾特扩展LazyColumn各条目统一10dp间距。定向编译通过，实际样式函数在严格span模型下覆盖45字符原始偏移、宿主span保留、重复样式去重、旧前缀隐藏与空文本；真实艾特分类回归通过。未运行Gradle、未构建APK、未操作微信；真实NeatTextView渲染及三色重进群聊仍待新包验收。

## 灰色提醒渲染入口修正

用户实机确认e8c8225不再闪退，但新旧提示仍灰色且旧前缀可见。源码确认绑定后处理只遍历TextView，而NeatTextView继承View，真实Neat消息渲染未接入；自定义CharacterStyle画笔shader也未沿用已适配的逐字颜色机制。现复用艾特高亮已使用的Neat/MMNeat/X2C签名扫描方式，排除静态、抽象和通用View/TextView方法，仅对模块不可见标记或旧前缀的输入应用样式。安装使用现有Dex调度器并检查Hook句柄，失败不标记成功。

三色文字改用逐Unicode码点ForegroundColorSpan，覆盖原灰色颜色span，保留非颜色宿主span；前缀继续以ReplacementSpan隐藏，原文与字符长度逐次检查保持一致。不再依赖独立shader绘制。原先TextView绑定后路径作为标准文本控件处理保留。普通聊天和时间文本无模块标记不处理。未新增微信内部猜测方法；只限微信8.0.78和项目已存在的渲染入口证据，其他版本未横向验证。

定向编译（宿主接口桩）、生产样式函数跨度测试通过：45字符偏移、重复着色、三色首尾颜色、代理对不截断、旧前缀隐藏及空文本。不能替代Neat实机渲染与旧前缀隐藏验收。用户本次e8c8225 mapping已持久保存用于追溯，不以mapping代替运行时渲染证据。

## 引用消息艾特隔离
当前消息缺少独立 msgSource 时，原 getMsgSource 的整段 XML 搜索可能回退到 refermsg 内的被引用消息，导致把原发送者的艾特归给引用者。现统一在公共消息模型的来源回退、艾特用户列表及分类前剔除引用区块；正文中的引用区块也不参与 @所有人判断。支持嵌套及未闭合引用隔离，CDATA/注释按不透明 XML token 处理。引用者自身有真实艾特时仍按当前消息来源判定。提醒展示、颜色和持久化去重不变；已插入的旧误报不自动删除。
验证：生产模型定向编译和引用回归通过，覆盖纯引用、引用内艾特我/所有人、引用同时自身艾特、外层来源回退和不完整引用；尚未实机验收。最初按要求保留本地，后与其它修复统一提交；未运行 Gradle、未构建 APK、未操作微信。

## 引用艾特仍误报：上游来源提取修正
用户反馈引用仍触发。进一步核查发现 WeChatMessageParseApi.resolveMsgSource 在 add_msg 入站时，先对整段 xml/content 调用 getXmlSection("msgsource")，且早于独立来源字段。这样 refermsg 中的来源被提取成独立字符串，模型收到时引用外壳已经丢失，上一轮模型层剔除无法生效；这是上一修复覆盖不足。
现在公共模型暴露 currentMessageXml 作为内部来源隔离工具，Java 入站解析在提取 msgsource 前先剔除引用，normalizeMsgSource 及字段回退同样隔离；剔除后为空时继续查找当前消息独立来源，不直接结束。没有禁用全部引用消息的艾特，引用者自身真实艾特仍保留。
验证：scripts/test_mention_source_pipeline.py 编译实际 WeChatMessageParseApi Java 类和 Kotlin 模型，执行来源提取→分类联动，覆盖仅引用、独立自身艾特/所有人、外层来源、备用字段含引用与空引用继续回退；scripts/test_mention_notice.py 补充提前提取后误归属的反例和边界回归，均通过。Android TextUtils 和反射依赖使用桩；这不是完整微信事件实机测试。未运行 Gradle、未构建 APK、未操作微信；经用户授权与玻璃背景修正一并提交推送。此前已插入的提醒不自动清理。
