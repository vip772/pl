# 会话原始归属恢复与启动等待日志

## 缺失备份的恢复方式

分组同步继续禁止猜测原始 parentRef。读取当前账号的 original_parent_refs 和 original_parent_refs_backup_v1 时，先剔除 Hchat 分组标识，再合并；有效主记录优先，无效主记录不再覆盖有效备份。两份都无有效记录时仍保留当前归属并报告错误，不能把日志降级当成数据修复。

分组菜单新增“修复会话恢复目标”：使用现有会话选择器选择直属会话，明确确认今后移出时回到微信首页。只对缺少可信备份的记录保存空 parentRef，已有可信备份不会覆盖；不直接移动当前会话。确认后再次验证账号、分组成员及数据库当前 parentRef。与常规同步共用串行后台执行器，先同步持久化主备记录，再请求常规同步；保存失败不进入同步。

此操作是用户指定未来恢复目标，不是找回历史归属。未执行操作前，历史缺失记录仍可报错。本轮未改写设备配置或数据库，也未替用户为任何群指定目标。

## 快捷已读

初次准备时数据库 API 或原生存储实例未就绪属于启动等待，改为去重 DEBUG 日志。方法定位失败仍为 WARN，异常仍为 ERROR。统一 DexInstallScheduler 的有限重试、安装失败警告和最终失败 ERROR 均保留；不增加轮询或 Hook。

无新增滚动监听、消息遍历、每帧任务或聊天布局处理。备份合并只发生在既有分组后台同步；手动修复仅按用户操作执行。确认弹窗在选择器关闭后的下一帧打开。
