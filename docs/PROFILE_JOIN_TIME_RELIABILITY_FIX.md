## 第二轮：新群/新成员与部分老成员缺失（基准 aca1d98）

本节为该提交之后的在途修复，不能沿用上一轮发布或验收结论。

### 源码确认及已落盘修改

1. 原群快照（包括空结果）在进程内永久有效，新成员无机会重新索引。现改为最多 32 群的访问顺序快照；缺失成员访问时，距离上次成功查询至少 15 秒才后台刷新。不是自动定时轮询，持续停留页面未触发读取时不保证自动更新。已命中的历史时间直接读取缓存。
2. 原索引成员仅来自 roomdata，其为空即停止。现合并联系人群成员 API、chatroom.memberlist 与 roomdata；仍无成员时不伪造时间。
3. 原系统消息只读取最早 20000 条，后续入群记录可能永远不可见。现流式读取群限定候选消息，关闭 Cursor，取消时停止；仍可能在大群产生较长后台扫描，尚无实机耗时数据。
4. 原单成员查询缺少 talker 约束，可能返回其他群的事件。现统一走当前群索引；仓库搜索未发现其他该单成员接口调用点。
5. 数据库消息表列表原永久缓存，可能遗漏进程内新建分表。新增显式刷新重载，仅当前进群索引使用；既有调用保留缓存行为。刷新枚举 sqlite_master 并检查新增表，发现失败不保存成功空快照。
6. 缓存和待处理群任务均限制为 32；任务登记带代际，旧任务不能移除新任务登记；注册/移除/排队同步，关闭后不重新创建执行器。无冷启动全群预热。

### 尚未闭环，不能宣布用户现象已全部解决

- 旧 isMemberJoinSystemMessage 仍只根据成员 ID 与泛化关键词判定；邀请人和被邀请人没有区分，通用 sysmsgtemplate 还可能误判其他事件。本轮没有把猜测的中文模板解析接入生产。
- 没有取得用户新群的实际原始入群消息、群 ID 与对应有效宿主日志。反编译结果只证明公共模板/link/memberlist/username 路径存在，不能据此确认新群实际格式。
- 没有历史入群消息、只有昵称而无可关联成员身份的消息，无法保证恢复真实时间；不使用建群时间、首次聊天时间或当前时间填补。
