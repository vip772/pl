# 引用回复正文艾特高亮

## 原因与范围

用户截图中带引用块的回复正文未高亮，普通文本中同名艾特高亮。对比 efe6d62 与 801d8f8：textHook、buildMentionText、渲染缓存及原生消息定位代码一致，旧文本入口已用 isText 拒绝 AppMsg。实际消息模型回归确认引用消息外层 49/0x31000031 不满足 isText，即使独立艾特名单存在也被拒绝。该代码缺口早于性能缓存修改；截图消息的实际 type/source 尚未取证，不声称所有漏色只有此原因。

## 修改

- 原生绑定允许 AppMsg 进入已有字段/数据库补全，随后通过 MentionHighlightScope 仅接受普通文字或自身 AppMsg 子类型 57 且有非空正文 title 的消息。其它 AppMsg 不进入高亮渲染。
- 引用消息每次文本 Hook 在缓存读取前检查作用范围：只接受完整文本与本次回复 title 精确一致的输入，不对引用预览或局部片段做子串替换。
- 提取正文前用公共 currentMessageXml 剔除 refermsg，再复用消息模型 title 的 CDATA、XML 实体和数字实体解码，不修改公共模型。
- 引用块与当前正文出现相同文本时缺少经逆向验证的控件角色区分，保守跳过（引用内容包含正文时即拒绝），避免给引用块套入本次发送者的成员点击行为。
- 艾特名单仍由现有模型从当前消息独立来源解析，引用块内旧名单不得提升成新名单。范围匹配、成员歧义拒绝、颜色与 ProfileSpan 同步写入均保留。
- 缓存、具名反射元数据优化及非群聊/图片等早退保留。为了补齐引用功能，AppMsg 在判断子类型前可能新增一次存储查询；未宣称该功能修复无新增成本。

## 验证与限制

scripts/test_mention_quote_scope.py 编译实际生产作用范围类和真实消息模型，覆盖普通文本、外层 49/高位49、子类型57、引用来源隔离、预览/片段/同文本歧义/非引用链接拒绝，以及 CDATA/实体/emoji。
scripts/test_mention_binding_lookup.py 提取生产转换代码并编译实际范围类，补充引用消息原生绑定→名单补充→正文接受，以及其它AppMsg拒绝；保留3000次元数据稳定命中回归。另运行现有来源管线回归。

未运行 Gradle 或构建 APK；没有新增 Hook 签名，未新做多版本 APK 逆向。JVM回归不能证明当前微信引用卡正文的 setText 时序、精确文本、字体颜色和点击行为均生效。没有放开全局 TextView Hook 或用姓名猜造真实艾特名单。同名歧义、无名单或原生渲染产生不同/分段文本仍可能保守不处理。

实机验收：原截图引用回复正文颜色/点击；引用块原文不被误染；普通艾特、无真实名单的纯文字、链接卡片、滚动复用；相同正文与引用预览歧义场景保持不处理。若正文仍漏色，需在实际绑定/渲染时记录类型、范围与跳过原因，不能盲目放宽所有卡片。
