# 聊天悬浮控件与沉浸式背景协调

悬浮标题栏接管 ActionBarContainer 的 primary/stacked/split 背景。原生 setter 的前置 Hook 保存最新背景并把本次参数置空，避免事后反射清空造成二次调用。沉浸式背景恢复这些层时交由当前所有者保存；退出悬浮模式后恢复。

输入框保留图标 Drawable 和原生前景，不给原本无背景的图标安装占位背景。沉浸式背景对非语音图标也保留前景。此修改消除过度清理路径，但尚无真机证据证明它就是偶发表情缺失的唯一原因。

微信 8.0.78 的发送动画 g0 按宽度差计算 alpha；宽度差为零可产生 NaN。h0/f0 的取消回调还会设置显隐，旧逻辑只恢复可见发送按钮的 alpha。新逻辑在 A/B 调用和动画结束/取消后合并一次任务，等相关动画停止后读取当前 r2/l4，仅在文字模式且按钮父容器可见时协调发送/附件按钮，并恢复发送宽度。正在运行的动画不受覆盖，脱离页面取消任务。

开销：输入表面缓存从列表逐项查找改为 IdentityHashMap；清理时使用局部变量保存边距，避免临时数组。未新增逐帧遍历、滚动监听、轮询或常驻日志。原有 pre-draw 仍维护已缓存的表面。

验证包括实际 Kotlin 生产辅助类行为测试、Android SDK 定向编译、面板/列表避让/透明度/背景作用域及分组栏回归。行为测试不是 Android 真机 UI 或性能验收。安装新版后需验收表情切换、快速输入清空、语音/文字切换、沉浸式背景开关及滚动帧表现。
