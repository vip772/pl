# 自动缓存、侧边栏入口与悬浮底栏透明度

## 设置入口

首页侧边栏使用原有 `HomeSidePanelSettingsProvider` 和页面，归入“增强”并设置新功能标记，因此同时出现在“新功能”。自动缓存同样使用单一 Provider，在“增强”和“新功能”中显示同一设置页；独立开关默认关闭，配置为 `Hchat_auto_cache_config/enable`。两项均接入已开启功能聚合和设置搜索。

悬浮底栏增加“底栏不透明度”滑块，范围 0–100%，默认 100% 保持既有效果。配置 `Hchat_custom_bottom_bar_config/custom_bottom_bar_opacity` 通过原有配置监听更新运行时，对整个悬浮底栏 Compose 图层生效，包括图标、文字、角标及玻璃表面。0% 时底栏完全透明，原点击区域仍保留。

## 自动缓存行为

- 通过 `WeChatApis.message().observe()` 接收新消息，仅处理入站图片、聊天视频和 AppMsg 类型 6 的文件文档，不限制发送人或群聊。
- 开关开启后处理新到消息，不扫描历史。微信进程必须运行并联网；不能补救已经过期、服务器不可下载的文件。
- 使用当前登录账号与会话、消息 ID 隔离任务；账号未就绪时不提交，切换账号后旧队列任务丢弃。
- 媒体元数据可能晚于消息到达，因此下载队列通过公共消息存储 API 补查最新记录，最多补查 20 次。聊天视频优先读取原生 `VideoInfo`，不要求消息正文包含视频 XML。
- 复用已有 Mars C2C CDN 下载器，不新增混淆类反射或 DexKit 定位。最多同时提交三个下载任务，待处理队列上限 512，溢出及失败记录 HLog 错误日志。
- 图片优先原图，缺少原图地址时使用中图，不把缩略图作为完整缓存。聊天视频文件类型为 4。附件普通类型为 5，大文件类型为 7。
- 保存到微信外部媒体目录下 `Hchat/AutoCache/Image`、`Video`、`File`。文件名带账号与消息键的 SHA-256 前缀，附件保留经过路径字符清理的文件名。下载使用独立临时文件，成功后检查非空及已知长度，再重命名为正式文件；已有完整文件不重复下载。
- 缓存是独立保存的副本，不修改微信原消息下载状态，也不伪造微信原生媒体路径。原消息过期后需要使用系统文件管理器从缓存目录打开。
- 关闭开关后不接受新任务，队列待执行任务会停止；已经交给微信下载器的任务可能继续完成。功能销毁时释放后台队列。网络下载十分钟未回调会记录超时。

## 逆向依据与验证范围

仓库已封装并记录的消息解析、图片和视频 CDN API 见 `WECHAT_APIS.md`。本次没有新增微信混淆类名、字段名或方法名。

附件 CDN 参数额外核对设备上微信 8.0.78 反编译产物：`smali_classes12/k04/l0.smali` 的 `task_NetSceneDownloadAppAttach` 链路把普通附件的 `field_fileType` 设为 5，大文件为 7，并读取 AppMessage 的 CDN fileid 和 AES key；`dx0/r.smali` 将协议 `appattach.islargefilemsg` 解析为大文件标记，且附件超过 `0x1900000`（25 MiB）时设置该标记。实现只使用协议字段，不硬编码这些混淆类。

设备现有可直接读取的附件逆向证据为 8.0.78；本次未补齐规则所列全部旧版本 APK 横向逆向，不能据此宣称全部版本附件下载已验证。图片、视频和消息观察继续复用仓库现有适配。特殊附件若需要额外服务器签名或不具备 CDN URL/AES key，当前可能下载失败并记录日志，不会把它标记为成功。

按用户要求未运行本地 Gradle、编译或构建。提交前做源代码调用签名、配置键、入口注册及 `git diff --check` 检查。实际构建及私聊、群聊、图片、视频、普通文件、大文件的收取和断网恢复行为，需要 GitHub 构建后实机验证。
