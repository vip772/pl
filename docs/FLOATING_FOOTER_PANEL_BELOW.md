# 悬浮输入框与表情、加号面板联动

表情和加号面板改为在输入框下方展开。输入列在上，ChatFooterBottom 在下，通过 RelativeLayout.BELOW 锚定到输入列；不再把输入列放到面板下方。

悬浮布局的负 topMargin 使用输入高度＋可见面板高度＋原有底部间隔。面板展开时整体上移，输入框底部贴住面板顶部；关闭时面板不计入高度，输入框恢复底部位置。消息列表底部 padding 同步使用完整占用高度，基于保存的原始 padding 计算，不累加、不显式滚动消息。

表情和加号面板不再应用模块自定的 180–265dp / 屏幕30% 高度限制，不再改写面板及子面板高度或缓存首次高度；沿用微信当前设置的布局参数和实际测量高度，仅据此计算悬浮位置及列表避让。保留点击入口和键盘状态处理。首次挂载时按当前面板状态决定可见性，避免正在展开的面板被重排逻辑强制隐藏。改动保存并恢复输入列原规则；禁用、脱离及失败回滚继续把面板放回原父容器和原索引。未新增微信内部类、字段或 Hook 签名，沿用现有已定位入口；本轮未扩展跨微信版本验证，当前测试环境为微信8.0.78。

验证：悬浮输入框、卡片视觉与输入表面生产文件通过 Android36 SDK＋DexKit 定向编译（外围项目依赖用桩）。生产占用高度计算模型覆盖面板开关、多行输入、底部间隔、面板高度变化和测量高度回退，验证输入底部等于面板顶部；原有消息列表 padding 回归通过。模型与SDK编译不等于完整Android布局或实机动画验收。未运行Gradle、未构建APK、未操作微信。

安装后开启悬浮输入框，分别从键盘关闭和打开状态切换表情、加号面板，确认面板在下、输入框贴住其顶部；互相切换及收起无错位，表情分页与加号工具可点，消息底部不被遮挡。无需发送消息。再关闭悬浮输入框，确认恢复原生结构。
## 原生面板高度回归
已删除压缩高度的两个调用点、实现、恢复缓存及相关常量，避免切换面板或键盘高度变化时沿用旧高度。相同设备方向、键盘和显示设置下，对比关闭/开启悬浮输入框时的表情与加号面板高度；同时检查分页、触摸、键盘互切和收起，输入框仍贴住面板顶部。沿用现有微信8.0.78入口，未新增内部签名，未完成跨版本或实机高度一致性验收。安装新版并重启微信后验证，旧进程不会热更新此改动。
