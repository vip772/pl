# 滚动性能后续修正

基于 f9d6f00 同步采样与用户反馈，改动尚待新包实机验证。

## 滑动引用 ID 成员复用

SwipeQuoteAdapter.messageId 委托 MessageIdAccessors。按实际 Class 身份缓存成功解析的方法和字段，只缓存元数据，不缓存原生消息或 ID 值。方法 getMsgId/getMsgID/getId 优先，字段 field_msgId/msgId/msgID/id 后备，保留正值和 Number/String 转换规则。

空值、异常和非正值仍按原顺序继续读取；不存在或解析失败的成员不缓存负结果，避免 KavaReflector 将异常转 null 后永久阻断重试。因此字段后备路径仍可能重复查找不存在的方法，不宣称全部反射查找消除。未合并一次绑定中的重复 ID 读取，也未改通用反射工具。

scripts/test_swipe_message_id.py：JVM 反射 stub 下 2004 项旧模型结果/调用顺序对照及1000次成功首选成员热读通过。测试不覆盖真实KavaRef、Android/R8和多ClassLoader实机行为。

## 纯隐藏模式背景 Hook 边界

用户确认五类条目隐藏验收成功，但开启相关功能后四个主页滚动明显掉帧。原实现无论是否有背景图都会安装全套背景渲染Hook；隐藏设置位于背景功能总开关之下，纯隐藏用户也会承担这些Hook的开销。这是源码确认的不必要工作，尚不能证明它解释所有掉帧。

现在仅当背景总开关启用且至少一个槽位有图片时安装渲染Hook；隐藏过滤单独安装。首次新增背景图通过revision通知补装；删除全部图片或关闭总开关时背景回调早退，并通过refreshAll清理原状态。已经装过的背景Hook在本进程内保留轻量条件判断，重启后纯隐藏模式不安装它们。

隐藏项集合初始化及设置变化时更新，g0.q重建直接复用；不再每次读取五个布尔设置。隐藏范围与7个原生key、原生隐藏集合恢复语义不变。无新增配置、资源或持久化缓存，备份结构不变。

scripts/test_background_render_gate.py：64组启用/图片组合和无图启动、首次有图补装、删除/恢复图片及关闭状态转换通过。安装方法使用stub，不是Android整包编译。scripts/test_me_entry_visibility.py的32组合及提取Hook语法检查通过。

若任意槽位已配置图片，仍需运行背景链路；本次不能承诺解决该场景的掉帧。新包应分别验收无图纯隐藏和有图背景场景的微信/通讯录/发现/我页面滚动、隐藏恢复、首次加图和删除最后图片。没有进行新包实机测量、Gradle构建或多版本逆向验证，不新增兼容性结论。


## 已配置背景图场景的继续处理

用户确认掉帧时配置了背景图。readNativeField现在按实际Class和字段名复用成功定位的Field，每次仍读取当前对象，保留父类查找及空值规则；定位失败不缓存。图片存在状态在初始化及配置变化时更新，滚动中的条件判断读取槽位集合，避免反复File.isFile/length。外部直接替换文件且不发配置通知时，需要重启微信刷新存在状态。

scripts/test_background_native_fields.py的600项字段对照及1000次实时读取通过，覆盖继承、缺失、空值和不同Class。背景状态转换64组回归重新通过。未修改行遍历与背景修复顺序，没有实机帧收益证据，不能宣称全部掉帧已解决。
