# 群聊分析API配置与模型选择交互修复

## 范围与原因

本次仅修改群聊分析的模型选择弹窗、API配置交互及当前方案保存，不涉及头像、自动勾选合并或总结日期/采样算法。

原模型选择弹窗固定为屏幕72%高度，内部列表又固定240dp，造成少量模型时底部大片留白。原“获取模型”直接发请求，无按钮加载状态。配置标题右侧是未安装点击监听的字符倒三角；方案栏切换只加载字段，不更新选中颜色，导致当前方案显示混乱。原保存配置与切换活动方案通过两次独立写入完成。

## 修改

- 模型选择复用已有showContentDialog：窗口WRAP_CONTENT，按可见屏幕上限限制高度，超长内容滚动；移除固定240dp列表高度和72%窗口高度。模型行最小48dp且允许内容换行。
- API配置也复用内容自适应弹窗，移除固定88%屏幕高度和强制填满视口。
- 右上角ProfileDropdownView使用Canvas/Path绘制实心橙色倒三角，52dp点击区域，包含无障碍描述。点击原生PopupMenu选择方案1/2，菜单勾选当前项。
- 删除原方案1/2横向按钮。标题下显示“当前选择：方案N（保存后使用）”，方案名称字段仍允许自定义。两套配置在本次弹窗内独立保留草稿，来回切换不会串用。
- 保存只持久化当前选中的方案；方案内容和活动方案ID由同一个SharedPreferences.Editor一次apply写入。取消不保存本次草稿或选择。再次打开从活动方案读取；生成总结继续使用configStore.activeProfile()。
- 测试连接和获取模型读取当前所见字段快照；请求期间禁用两项请求按钮、方案切换、字段及保存，避免重复请求或跨方案回填。“获取模型”立即变为“获取中…”，完成后恢复，成功弹出列表，空列表/错误提示原因。原10秒连接/读取超时保持不变，并非总请求耗时保证。
- 配置弹窗关闭时清理原生菜单、模型子弹窗、AI实例、连接及延时回调；关闭标记和请求序号拦截迟到回调。

配置继续使用原统一HchatStorage用户库及原字段，保留方案1旧配置迁移；不新增持久化缓存或资源。
