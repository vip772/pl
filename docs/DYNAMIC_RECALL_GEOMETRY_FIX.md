# 动态撤回描边尺寸同步与缓存修复

基线：dev / eed2f2cfcaf47b02b6ae53294b8d1098788c34b6。与本地视频号时间边缘对齐修复统一提交。

## 已确认的代码缺口

`DynamicRecallRuntime.RecallStroke` 原先只在 `update()` 中依据内容宽高构建描边，而绘制时只更新内容相对消息行的位置。内容尺寸在布局回调与绘制之间变化时，会使用新位置和旧宽高。对仍为同一个内容 View 的后续尺寸变化，绘制路径本身没有同步措施。旧实现还在每次全局布局刷新时重新解析颜色、创建渐变并重建几何，即使尺寸未变。

这是源码中可确定的时序缺口；未获取故障瞬间的视图树，不能声称已经排除内容锚点或宿主裁剪导致的其他异常，也不能以该缺口证明用户截图全部问题的唯一根因。

## 修改

- 在绘制尺寸有效性判断前同步当前宿主边界及内容宽高，尺寸变更立即更新描边。
- 缓存内容宽高、线宽、density 和颜色配置；尺寸和配置均不变时直接返回。
- 颜色变化只重建渐变；几何变化才重建 Path/PathMeasure 和虚线数量。仅宿主行尺寸变化不重建内容路径。
- 保留原动画帧调度、离屏降频、detach/关闭/复用清理，不增加监听、线程、全局扫描或逐帧反射。不改宿主布局和气泡背景。
