# 朋友圈防撤回安装状态修复

2026-10-26运行日志中，功能首次直接install之后，DexReady再次通过DexInstallScheduler调用同一个hooker。原实现只统计本次新增Hook，已安装方法被hookedMethods跳过并返回0，导致重复安装返回false并产生多余重试。用户已确认实际防撤回正常，此处属于安装状态误报，不能等同于业务失效。

本次保持原安装入口、定位、缓存、成功阈值及防撤回业务逻辑不变：数据库入口与旧版主页开关已确认挂载时，重复调用计为有效；新候选仍继续尝试补装。数据库或主页开关挂载抛异常时，撤销提前加入的去重标记，防止失败被永久跳过；数据库异常记录具体方法。install串行化，避免重入将尚未完成的标记当作成功。

没有引入installed全局提前返回，避免丢失后续数据库包装类补装。成功标准仍沿用原有“至少一个匹配入口可用”，不意味着所有子功能入口都完整安装。防撤回、评论合并、查询处理、配置键与资源路径均未改变；没有增加聊天滚动、每帧绘制或数据库回调工作。
