# 聊天时间解析：反射元数据缓存

## 范围与依据

在 74aeb47 的有效三轮聊天滚动采样中，聊天时间绑定路径反复出现递归解析及 `KavaReflector.declaredFields` 调用。此次只优化 `ChatTimeStyleRuntime` 的元数据查找，不改变 Hook 定位、时间格式、绑定生命周期或消息识别条件；不修改全局反射封装、艾特高亮、消息详情、背景与底部布局。

## 实现

- 运行时独立的同步访问 LRU，最多保留 128 个真实 `Class` 的条目。以 Class 身份区分不同 ClassLoader，同名类不共用反射成员。
- 按需缓存每个类用于递归的字段列表、零参数具名方法，以及具名声明字段。方法仍通过原有 `findMethod` 定位；字段仍逐级查找父类，不改变优先级。
- 空字段列表和未找到的成员也缓存，避免对不支持的类重复扫描。
- 缓存仅保存反射元数据，不保存消息、字段值、消息 ID 或创建时间；每次解析仍读取当前对象。原有最多四层递归、身份访问集合、集合/数组处理、静态/基础字段过滤及有效 ID/时间校验不变。
- 淘汰仅导致下次重新查找；运行时 destroy 清空新增缓存。缓存有界强引用，不承诺存活期间立即卸载 ClassLoader。
- 同步锁只包围元数据查询和填充，不包围宿主方法执行或字段读取。

## 验证

执行 `python3 scripts/test_chat_time_resolution.py`，提取并编译实际生产解析方法和缓存声明；宿主反射使用计数桩，不执行 Gradle。

覆盖：首次与嵌套解析、集合、无效 ID/时间、同一消息对象值变化、包装对象替换、继承字段、getter/字段优先级及值失效后的回退、缺失成员负缓存、循环与深度上限、相同全限定名不同 ClassLoader、128 类容量上限及清空后重建。稳定命中 3000 次解析时不再调用元数据查找桩，仍每次读取最新时间。另对生产 destroy 清理连接做源码断言；并非完整 Android 生命周期执行测试。

限制：这是提取生产逻辑的定向 JVM 回归，KavaReflector 与 Android 宿主使用桩，不等于完整工程编译、R8 包验证或多版本微信实机验证。本次未新增内部签名或更换 Hook；未重新对各版本 APK 做逆向。首次构建缓存、缓存锁与 LRU 访问仍有成本；超过容量会重新查找，不能称为零反射开销。性能收益须安装对应构建后，用同次 mapping 进行同条件 CPU/帧复测确认。
