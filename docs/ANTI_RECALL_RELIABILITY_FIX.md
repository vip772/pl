# 防撤回可靠性与标记定位修复记录

基准：dev / 812b6abff1a702f3e3c0102fbbbd2b392ea5baa7。
用户要求：只做 SDK 定向编译与静态检查，不运行 Gradle、不构建 APK；本轮不提交、不推送。

## 本轮范围

1. 原消息只按会话和服务器消息 ID 查询，并校验会话、服务器 ID、非撤回状态；移除服务器 ID 当本地 ID 查询以及错误时间查询。优先使用原生入口提供的目标 ID，XML newmsgid 作为解析来源，不再把外层通知 addMsg.r 或旧 msgid 当服务器目标 ID。
2. 核心拦截结果在事件发布、标记保存、提示生成之前设置；解析/查询失败隔离。Hook 外层吞住并记录异常，避免异常外泄让 Xposed 重置已设置的结果。自己撤回仍尊重“保留自己撤回”。
3. 逐 Method 登记已安装 Hook，部分失败允许重试且不会重复安装成功入口；数据库和媒体保护定位失败不阻断主入口安装。使用独占安装票据和 OwnedHooks，销毁时清理票据、Hook、提示任务和缓存；重新开启可重新触发未完成安装。延迟提示绑定原所属 Hook 代际。
4. 防撤回主开关纳入 hchatextra 运行时依赖并独立监听，不再要求四个扩展功能中至少开启一项；共享运行时已有四项业务仍保留原有控制。
5. 撤回专用锚点优先选择原生 clickArea/main container，要求可见、有效尺寸且处于行内，再回退卡片内容；不改变消息时间等功能共用的锚点函数。标记每次绘制读取当前位置，图标 Path 复用；保留 50% 内容淡化与原透明度恢复。
6. 临时消息不会覆盖同 ID 已有的数据库消息缓存。
