# 收藏语音按需下载与试听

## 问题与交互
聊天＋号面板的收藏列表原先在点击时立即要求本地语音文件可用，否则提示“收藏语音文件不存在”并中断宿主点击，必须先在原生收藏播放以准备文件。

现在有效收藏语音条目先显示发送确认弹窗；不在打开时访问媒体或触发下载。点击预览才在 IO 线程解析本地/VFS 文件，缺失时复用 FavoriteVoiceResolver 的下载定位，在主线程实际发起下载，后台协程最多每 500ms 检查一次，等待 60 秒，文件可用后转码并自动试听。点击发送同样可先下载，无须先试听；仅这次明确的发送操作在准备完成且弹窗有效时执行。忙碌时预览和发送点击不重复执行，取消始终可用。失败或超时停留弹窗允许重试。

## 取消与范围
关闭、取消或销毁组合时使请求无效并取消协程等待；发送前在主线程做最后有效性校验，校验与发送之间不挂起。播放器销毁释放，并忽略已销毁播放器的迟到 prepared 回调。微信原生下载已发出后可能继续完成，但不会因该完成而自动试听或发送。已进入发送 API 的操作不能撤回。

仅聊天收藏选择入口接入新交互；原收藏长按菜单和其它公共发送入口保持原行为。播放器新增 autoPlay 参数默认关闭，仅新确认弹窗启用，不改变其它预览自动播放策略。公共文件解析排除零字节普通文件。未新增反射入口或修改 DexKit 匹配，复用已有缓存定位和签名。

## 逆向与验证
再次核对目标 8.0.78 的 FavoriteVoiceDetailUI.onCreate，包含 key_detail_data_id、key_detail_info_id、get fav item info error，调用 tc2.s2.F0(tc2.m3,boolean) 下载入口；复用解析器的稳定字符串及调用关系定位，不将此混淆签名硬编码。历史多版本证据见 WECHAT_APIS.md，本次不宣称完成其它版本重新实测。

scripts/test_favorite_voice_preparation.py 执行生产协程准备函数：本地文件不启动下载、缺失后就绪、启动失败、超时、等待/启动前/下载派发期间取消不执行后续动作；静态断言选择点击没有本地文件前置条件。确认弹窗、播放器及控件通过实际 Compose 插件与 Android SDK 定向编译；完整 FavoriteVoiceResolver 和准备函数通过 SDK/DexKit 定向编译，部分宿主接口使用桩。此前艾特分类、配置备份和设置底部布局回归一起执行。
